# dead-parameter-external-api

זהה קריאה ל-API חיצוני עם פרמטר, דגל או שדה **שאינו קיים בחתימה** — ושעטוף ב-`try/except` שמסתיר את זה. הצורה נראית אחראית במיוחד: יש טיפול בשגיאות, יש הודעה מסבירה, יש מסלול חלופי. בפועל הקריאה נכשלת כבר בקשירת הארגומנטים, לפני שגוף ה-SDK רץ — כלומר נכנסים ל-`try`, מתים בשורה הראשונה שבו, וה-`except` הוא המסלול היחיד שמסתיים אי פעם.

## דווח כשמתקיים אחד מהבאים

1. **`except TypeError` / `except AttributeError` סביב קריאה ל-SDK, שהמסלול החלופי שלו הוא אותה קריאה בלי הפרמטר.** ‏**זהו טריגר לבדיקה, לא ראיה.** שתי החריגות האלה נזרקות גם מתוך גוף ה-SDK מסיבות לגיטימיות לגמרי (ערך מטיפוס לא צפוי, אובייקט שלא אותחל). לפני שמדווחים — לוודא **אחד משניים**: שהחתימה במקור אינה מכילה את הפרמטר, או שהחריגה נוצרה ב**קשירת הארגומנטים** ולא בתוך הגוף (ההודעה של פייתון אומרת זאת: `got an unexpected keyword argument`). חריגה שנוצרה בתוך הגוף אינה הדפוס הזה.

2. **הודעת הפולבאק מתארת התנהגות שלא נבדקה.** ‏"falling back without execution stats" בזמן שהמנוע מריץ דווקא את המצב הכבד ביותר — ההודעה הופכת לתיעוד שגוי שכל מי שקורא את הלוג מאמין לו.

3. **פרמטר שמגיע מהממשק, עובר שכבות, ולא משפיע על שום דבר.** הבדיקה: לשנות אותו ולראות אם משהו בפלט משתנה. תפריט שלא עושה כלום הוא הסימפטום.

4. **"תיקון" סינטקטי לקריאה שנכשלת** — מ-positional ל-keyword, שינוי שם ארגומנט, הוספת `**kwargs` — בלי לפתוח את החתימה במקור. זה טלאי על API שאולי לא קיים, והוא מאריך את חיי הבאג.

5. **דגל שמועבר ל-SDK ואינו מופיע בתיעוד של הגרסה המותקנת.** גרסה נבדקת מ-`requirements.txt` **ומהמותקן בפועל**; כשהם נבדלים, המותקן מנצח.

## איך מוודאים

לפתוח את החתימה בקוד הספרייה או בתיעוד הגרסה המותקנת — `source-driven-development`. ואימות נפרד: להריץ פעם אחת עם `raise` במקום הטיפול בחריגה, ולראות אם הקוד בכלל מגיע לשם. ‏`except` שאף פעם לא נכנס ו-`except` שתמיד נכנס נראים אותו דבר בסקירה.

## False positives

- `try/except TypeError` שמכסה **בכוונה** שתי גרסאות של ספרייה, עם הערה שאומרת אילו.
- פרמטרים אופציונליים אמיתיים שנבדקו במקור.

## חומרה

MEDIUM — פיצ'ר שקט שלא עובד, ולוג שמתאר את ההפך ממה שקורה. עולה ל-HIGH כשהפרמטר האבוד הוא בקרת בטיחות (מצב "בטוח" שנבחר ולא נאכף, כמו `queryPlanner` מול `allPlansExecution` בפרודקשן).
