# rtl-geometry-and-clamp

זהה חישוב מיקום או גודל שנכתב מתוך ההנחה שהציר מתחיל משמאל, והצמדה לגבולות המסך שמצמידה מיקום בלי לצמצם גודל. שתיהן נכונות ב-LTR ובחלון רחב, ולכן הן עוברות סקירה וגם עוברות את הבדיקה — שנכתבה באותה הנחה.

## דווח כשמתקיים אחד מהבאים

1. **`clientX` / `pageX` / `offsetX` בחיסור, בלי שהסימן נגזר מהפריסה.** `startWidth + (clientX - startX)` היא נוסחת LTR. ב-RTL האלמנט זז הפוך מהאצבע. הצורה הנכונה: `getComputedStyle(el).direction` או מדידה בפועל קובעים את הסימן.

2. **`left` / `right` / `marginLeft` שנקבעים ישירות** בפריסה שיכולה להיות RTL — במקום `inset-inline-start` / logical properties.

3. **הצמדה ל-viewport בלי צמצום גודל.** `Math.min(x, vpW - w)` כש-`w > vpW` נותן ערך שלילי, האלמנט נדחף לקצה וממשיך לגלוש. ‏**הדגל האדום החמור:** כשידית הגרירה או ידית שינוי הגודל הן הדרך היחידה לחלץ את האלמנט — הן בדיוק מה שיוצא מהמסך, וזו תקיעה ולא אי-נוחות. לצמצם קודם: `w = Math.min(w, vpW - margin)`.

4. **אותו מימד שנקבע ביותר ממקום אחד** — `max-height` ב-CSS מול `calc()` ב-JS, או שני קבצי CSS. הם נסחפים, והפער נבלע ב-`overflow: hidden` בלי סימן.

5. **`overflow: hidden` על מכל שגובהו מחושב** — הוא הופך שגיאת חישוב לתוכן שנעלם ואינו נגיש בשום גלילה.

6. **אייקון כיווני** (חץ, "הבא", "אחורה") שאינו מתהפך ב-RTL.

## האימות שתופס את זה

לא קריאת קוד: מדידה בדפדפן אמיתי **בשתי הפריסות**, עם ריצת בקרה על הקוד שלפני התיקון — ושני המספרים מצורפים, לפני ואחרי. שלושת המופעים המתועדים נתפסו כך ולא אחרת.

## False positives

- ממשק שמוצהר כ-LTR בלבד (עורך קוד, טרמינל, לוח מספרים) גם בעמוד עברי.
- קנבס / SVG עם מערכת צירים משלו שאינה מושפעת מ-`direction`.

## חומרה

HIGH כשהתוצאה היא אלמנט שלא ניתן לחלץ או תוכן שלא ניתן להגיע אליו. MEDIUM לסטיית מיקום.
