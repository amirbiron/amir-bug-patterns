# line-number-coupling

זהה הפניות קשיחות למספרי שורות בקבצים ארוכי-חיים — תיעוד, הערות קוד,
קונפיגורציה — שנשברות בשקט ברגע שהקובץ המופנה משתנה.

## דווח כשמתקיים אחד מהבאים

1. **`literalinclude` עם `:lines:`** בתיעוד Sphinx, כשקיימת חלופה סמנטית:
   `:pyobject:` לפונקציה/מחלקה, או `:start-after:`+`:end-before:` עם
   עוגני טקסט. טווח שורות מצביע על קוד אחר אחרי כל תזוזה — והתיעוד ממשיך
   להתקמפל ומציג את הקוד הלא נכון, או מפיל build עם `fail_on_warning`.

2. **הפניית `file.py:123` בהערת קוד או במסמך** שאמורים לחיות לאורך זמן.
   העדף שם פונקציה/מחלקה, עוגן טקסטואלי, או קישור permalink עם SHA.

3. **טסט שמאמת מיקום שורה** (`assert ... in lines[42]`) במקום תוכן.

## False positives

- `:lines:` על קבצים סטטיים שלא משתנים (fixtures ייעודיים לתיעוד).
- הפניות שורה בהודעות commit, בהערות PR, בלוגים ובממצאי ריוויו — ההקשר
  שלהן נקודתי לזמן הכתיבה, והן לא אמורות לשרוד תזוזות.
- קישורי GitHub עם SHA מקובע (`blob/<sha>/file.py#L123`) — יציבים.

## חומרה

MEDIUM — בפרויקטים עם `fail_on_warning` זה מפיל את build התיעוד כולו;
בלעדיו, התיעוד מציג בשקט קוד שגוי.

## ראיות

CodeBot PR #3232: `docs/conversation-handlers.rst` עם `:lines: 697-792`
נשבר כשהפונקציה זזה והפיל את RTD; הוחלף ב-`:pyobject:`.
