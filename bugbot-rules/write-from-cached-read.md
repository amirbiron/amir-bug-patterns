# write-from-cached-read

זהה מסלול שכותב — `insert_one`, `update_*`, `replace_one`, `save_*`, או פונקציה שבונה מסמך שנשלח לאחת מהן — שחלק ממה שהוא כותב, או החלטה שהוא מקבל לפני הכתיבה, נגזר מקריאה שעוברת דרך **קאש**: פונקציה מעוטרת ב-`@cached` / `lru_cache` / `cache`, או getter שקורא מ-Redis או ממילון בזיכרון.

> **לפני הכול — מאיפה הגיע המסמך שקראת?** ‏`find_one` ישיר על האוסף, או getter שידוע שאינו מקוּש — מחוץ להיקף, ואין כאן מה לבדוק. ב-CodeBot זו התשובה ב-19 מתוך 20 המקומות שבהם הטוקנים של שורת הטריגר מופיעים (נספר ב-`da4d9821`, בקוד הייצור בלי טסטים).

**למה זה חוזר:** שם הפונקציה אינו אומר שהיא מקוּשה. ‏`get_latest_version` נשמע כמו "תביא את האחרון", והדקורטור יושב רחוק מהקורא. מי שכותב מסלול שמירה ורוצה "את הגרסה הקודמת" מוצא את הפונקציה הכי ברורה בשם — ובדיוק אותה אסור לו. ולמה זה מסתתר: הטסטים רצים בלי הקאש או מול דמות שאינה עוברת דרכו, וה-TTL קצר, כך שהבאג מופיע רק כששתי כתיבות במסלולים שונים נוחתות בתוך החלון.

## דווח כשמתקיים אחד מהבאים

1. **שדה שמועתק לכתיבה מתוצאה מקוּשה.** ‏`existing = get_latest_*(...)` ואחריו `existing.get("x")` שנכנס למסמך שנכתב — תיאור, תגיות, דגל, תאריך, ובמיוחד **גוף הקובץ**. שינוי שנעשה במסלול אחר בתוך חלון ה-TTL מתהפך בשקט.

2. **מזהה או מונה שנגזר מתוצאה מקוּשה** — מספר גרסה, רצף, "הבא בתור". ערך ישן מייצר שני מסמכים עם אותו מספר.

3. **החלטת שמירה לפי תוצאה מקוּשה** — "השם תפוס", "הקובץ קיים", "כבר מסומן". כשהקאש אינו שומר `None`, "לא קיים" אינו יכול להיות ישן; **"קיים" כן יכול** — והתוצאה היא סירוב שגוי, לא אובדן, ולכן במקום אחר בסולם החומרה.

4. **ערך שעבר סריאליזציה בקאש ונכתב חזרה.** בקאש שעובר דרך JSON רק `str`, ‏`int`, ‏`float`, ‏`bool`, ‏`None`, ‏`list` ו-`dict` שמפתחותיו מחרוזות חוזרים באותו טיפוס. ‏`tuple` חוזר כ-`list`, ומפתח מילון שאינו מחרוזת חוזר כמחרוזת (`1` ← `'1'`) — שניהם מטבלת ההמרה ומההערה על מפתחות בתיעוד (https://docs.python.org/3.11/library/json.html). וכל מה ש-JSON אינו יודע לייצג, כמו `datetime` ו-`ObjectId`, עובר דרך `default=str` וחוזר כמחרוזת — ‏`default` הוא *"a function that gets called for objects that can’t otherwise be serialized"*. נמדד ב-Python 3.11 דרך הדקורטור `@cached` של CodeBot עצמו, במסלול Redis (מול fakeredis) ובמסלול המקומי: ‏`datetime` חוזר כ-`'2026-09-02 10:00:00+00:00'`, ‏`ObjectId` כמחרוזת hex, ו-`True` ו-`None` חוזרים כמו שהם. מה שנכתב חזרה נשמר במסד כמחרוזת, ושאילתה עם ערך תאריך כבר לא מוצאת את המסמך — מונגו משווה רק לשדה מאותו טיפוס BSON (*"only on documents where the BSON type of the target field matches the query operand type"*, https://www.mongodb.com/docs/manual/reference/bson-type-comparison-order/) — ובמיון לפי השדה הוא יורד מתחת לכל התאריכים. ‏`BY-STACK/mongodb.md` דפוס 3 הוא אותו כשל מהצד של השאילתה.

5. **שכבה שחושפת רק קריאה מקוּשה.** facade, repository או backend שכל מי שכותב דרכו יכול לקרוא **רק** דרך הקאש, בזמן שהקריאה הטרייה קיימת — פרטית, או בשכבה אחרת. אין כאן שורה שגויה אחת; השכבה הזו היא שמייצרת את המופע הבא, כי הקורא לא יכול לקרוא טרי גם כשהוא רוצה.

## התיקון

1. **דלת טרייה בכל שכבה שכותבים דרכה.** מסלול שכותב קורא את מה שהוא כותב מהמקור, בלי הקאש — ולשם כך כל שכבה שכותבים דרכה חושפת גם קריאה טרייה, ולא רק את המקוּשה.
2. **והדלת הבטוחה נושאת את השם הפשוט.** בצורה הנכונה הקריאה הטרייה היא זו שנקראת `get_latest_version`, והמקוּשה נושאת את הקאש בשמה — למשל `get_latest_version_cached`. כך מי שמחפש "את האחרון" מקבל את הבטוחה, והקאש הוא בחירה מודעת של מסלול תצוגה. כשהשמות הפוכים היום — השם התמים מקוּש והטרי פרטי או עם סיומת — שני הסעיפים הבאים הם מה שמחזיק את הנכונות עד שמחליפים.
3. **שומר מבני:** בדיקה שסורקת פונקציות שקוראות דרך הגטר המקוּש ואחר כך כותבות באותה פונקציה, ונכשלת עליהן. קריאה **אחרי** כתיבה — לדיווח על מה שנשמר — עוברת. ב-CodeBot סריקה כזו מוצאת בדיוק שש פונקציות (הפירוט ב-Pattern 19), ומעבירה את שלוש הפונקציות שקוראות אחרי הכתיבה.
4. **בדיקת התנהגות שמחממת את הקאש לפני הכתיבה:** קוראת דרך הגטר המקוּש, משנה את המסד ישירות, מוודאת שהקאש **עדיין** מחזיק את הערך הישן — אחרת הבדיקה אינה בודקת כלום — ורק אז כותבת ובודקת מה נשמר. דמות שמחליפה את הגטר בלי הקאש אינה ראיה: היא מסירה בדיוק את השכבה שבה הבאג (`TESTING-PATTERNS.md` T1).

## False positives

- קריאה מקוּשה שמשמשת רק **להצגה** או לתשובה, ולא נכתבת.
- קריאה **אחרי** כתיבה שביטלה את הקאש של אותו מפתח באותו תהליך — כשהביטול נבדק (ראה `return-value-failure-unchecked.md`, הסעיף "תוצאת invalidation לא נבדקת").
- בדיקת "האם קיים" מול קאש שאינו שומר `None`, כשהמסלול פועל רק על "לא קיים" — ‏"לא קיים" אינו יכול להיות ישן.

## חומרה

HIGH כשמה שנכתב מהקאש הוא גוף הקובץ או מספר גרסה — עריכה שנבנית על בסיס ישן, או שתי גרסאות עם אותו מספר. MEDIUM כשזה מטא-דאטה — תיאור, תגיות, דגל, תאריך — שהשינוי בו מתהפך בשקט. LOW לסירוב שגוי ("השם תפוס" על שם פנוי), שאין בו אובדן והוא נעלם כשהקאש פג. בשום מקרה אין שגיאה או לוג.
