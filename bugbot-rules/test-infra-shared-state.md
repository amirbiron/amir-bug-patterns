# test-infra-shared-state

זהה כשלים שנראים כמו באג בספרייה או בקוד, ובעצם נובעים מהאופן שבו
הבדיקות מורכבות.

## דווח כשמתקיים אחד מהבאים

1. `from ...conftest import X` כאשר `X` מעוטר ב-`@pytest.fixture`.
   pytest מוצא fixtures ב-conftest לבד; ייבוא מפורש **עלול לרשום אותם
   מחדש** במודול המייבא עם cache נפרד, ואז `scope="session"` רץ
   פעמיים. התוצאה תלויה בסדר האיסוף, אבל הייבוא מיותר בכל מקרה —
   ולכן הכלל מוחלט. ייבוא קבועים ופונקציות עזר מ-conftest תקין.

2. mock, singleton או מודול עם state שאין לו איפוס ב-fixture teardown.
   התוצאה היא בדיקות שעוברות ונכשלות בלי דטרמיניזם.

3. בדיקה שנכשלת רק כשהיא רצה יחד עם אחרות, או רק בסדר מסוים.

## False positives

- ייבוא קבועים, פונקציות עזר, או מחלקות מ-conftest.
- fixtures עם `scope="function"` — הבעיה חמורה פחות, אך הייבוא עדיין
  מיותר.

## חומרה

LOW — לא מגיע לפרודקשן, אבל שורף שעות debug כי התסמין מצביע על
המקום הלא נכון.
