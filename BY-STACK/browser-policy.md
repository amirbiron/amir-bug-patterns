# מדיניות שהדפדפן אוכף — והשרת לא רואה

**מתי להחיל:** כל אפליקציה שמגישה HTML, מגדירה CSP, `SameSite`, CORS,
או משתמשת ב-`postMessage` / iframes / OAuth בדפדפן.

**המכנה המשותף:** האכיפה קורית **בצד הלקוח**. כשהיא חוסמת משהו, השרת
לא מקבל בקשה — אין `403`, אין לוג, אין שום עקבה. מבחוץ זה נראה בדיוק
כמו כפתור שבור או פיצ'ר שלא מגיב.

זה מה שהופך את המשפחה הזו למסוכנת: **כל כלי ה-debug הרגילים מראים
"הכול תקין"**, כי מבחינת השרת באמת לא קרה כלום.

---

## B1. מדיניות גורפת שנכתבה לפי הרוב, חונקת מקרה יחיד

**חומרה:** HIGH — כשל שקט לחלוטין

### איך זה נראה

הנחיה מסוג `'none'` נכתבת פעם אחת, כשהמקרה החריג עוד לא קיים. היא
נכונה ביום שנכתבה. חודשים אחר כך מישהו מוסיף את המקרה החריג — ולא
יודע שהמדיניות קיימת.

### דוגמה אמיתית

**Markdown-Docs (#21):** ה-CSP כלל `form-action 'none'`, כי האפליקציה
היא SPA בלי טפסי HTML. ואז נוסף **טופס אחד** — מסך אישור ה-OAuth.
הדפדפן בלע את הלחיצה:

```
Refused to send form data to '/mcp-consent' because it violates
the following Content Security Policy directive: "form-action 'none'".
```

בשרת לא הופיע כלום. הבקשה מעולם לא נשלחה. ארבע בדיקות שרת עברו.

### המשפחה המלאה

| הנחיה | מה נשבר בשקט |
|---|---|
| `form-action 'none'` | טופס HTML יחיד באפליקציית SPA |
| `SameSite=Strict` | חזרה מ-OAuth של ספק חיצוני |
| `connect-src 'self'` | `fetch` ראשון לדומיין חיצוני |
| `frame-ancestors 'none'` | הטמעה לגיטימית שנוספה מאוחר |
| `img-src 'self'` | אווטאר או תמונה מ-CDN |
| allowlist של CORS | סביבת preview חדשה |
| `Permissions-Policy` | מיקרופון/מצלמה בפיצ'ר חדש |

### כלל לזיהוי

1. הנחיית CSP עם `'none'` בפרויקט שמגיש HTML — לדרוש הערה שאומרת
   **איפה ההיתר יינתן** כשהמקרה החריג יגיע, לא רק "אנחנו לא משתמשים".
2. תגובת HTML שמכילה `<form>`, `<iframe>`, או `fetch` לדומיין חיצוני,
   באפליקציה שיש לה CSP גלובלי — לוודא שההנחיה הרלוונטית מתירה אותה.
3. פיצ'ר שנכשל **בלי שום עקבה בשרת** — לבדוק מדיניות לפני שמחפשים
   באג בקוד.

### התיקון המומלץ

היתר **פר-תגובה**, לא הרפיה גלובלית. מידלוור כותרות שמשתמש
ב-`setdefault` מאפשר לתגובה בודדת להביא מדיניות משלה:

```python
response.headers.setdefault(header, value)   # לא דורס
```

והמדיניות של אותו דף צריכה להיות **מחמירה מהגלובלית** בכל כיוון אחר,
ומרפה רק במה שהדף באמת עושה. דף עצמאי בלי JS יכול לקבל
`default-src 'none'` ובלי `script-src` בכלל.

### False positives

- שירות API בלי HTML — CSP לא רלוונטי.
- הנחיה שבאמת אין לה מקרה חריג בפרויקט.

## B2. ערך פגום בהנחיית מדיניות גרוע מערך חסר

**חומרה:** MEDIUM
**קשור ל-`CORE-PATTERNS.md` U3**, בזווית של דקדוק

### איך זה נראה

בונים הנחיית מדיניות ממחרוזת חיצונית. הערך אינו חוקי בדקדוק היעד.
הדפדפן פוסל את ההנחיה — ואז **הפיצ'ר חסום לגמרי**, כאילו כתבנו
`'none'`.

### דוגמה אמיתית

**Markdown-Docs (#21):** בניית `form-action` מ-`redirect_uri` של לקוח
שנרשם דרך Dynamic Client Registration:

```python
return f"{parsed.scheme}://{parsed.netloc}"   # שגוי
```

`netloc` כולל פרטי הזדהות. `https://user:pass@host` אינו
`host-source` חוקי. הרישום פתוח לכל דורש, ולכן זה קלט ממשי.

הגרסה השנייה חתכה userinfo אבל החזירה IPv6 בסוגריים — **גם שגוי.**
הדקדוק אינו מגדיר `IP-literal` כלל:

```
host-part = "*" / [ "*." ] 1*host-char *( "." 1*host-char) [ "." ]
host-char = ALPHA / DIGIT / "-"
```

### כלל לזיהוי

1. f-string או קונקטנציה שמכניסים ערך חיצוני לתוך `Content-Security-Policy`,
   `Set-Cookie`, `Location`, או כל כותרת אחרת.
2. שימוש ב-`urlsplit(...).netloc` לבניית origin — הוא כולל userinfo.
   `hostname` ו-`port` בנפרד, ואז אימות.
3. ניקוי תווים אסורים (blocklist) במקום אימות מול הדקדוק (allowlist).

### התיקון המומלץ

**allowlist מול הדקדוק, לא blocklist של תווים.** רשימת מה שאסור לעולם
אינה שלמה. עבור `host-source`:

```python
_CSP_HOST = re.compile(r"[A-Za-z0-9-]+(?:\.[A-Za-z0-9-]+)*\.?")
```

וכל מה שלא תואם — **מושמט**, לא נדחף פגום. נופלים מעצמם: userinfo,
IPv6, דומיין לא-ASCII, רווח, ו-`;` שגם מפצל את הכותרת עצמה.

## B3. הפניה בולעת את הכותרות שהתשובה נשענת עליהן

**חומרה:** MEDIUM

### איך זה נראה

נתיב מחזיר `3xx` לפני שהוא מגיע ל-handler שמייצר את הכותרת. הלקוח
רואה את ההפניה, לא את הכותרת, ולא יודע מה נדרש ממנו.

### דוגמה אמיתית

**Markdown-Docs (#19):** `Mount` של Starlette רושם `^/mcp/(?P<path>.*)$`.
בקשה ל-`/mcp` בלי לוכסן מקבלת `307` ל-`/mcp/`. ההפניה **אינה נושאת
`WWW-Authenticate`** — הלקוח לא ראה אתגר אימות ולא התחיל OAuth.

### כלל לזיהוי

1. נתיב שמחזיר `401` / `429` / `3xx` עם כותרת משמעותית
   (`WWW-Authenticate`, `Retry-After`, `Location`), שיושב מאחורי
   `Mount` / rewrite / trailing-slash redirect.
2. `app.mount(path, sub)` — לוודא ש-`path` בלי לוכסן נענה ישירות ולא
   דרך `307`.

### התיקון המומלץ

נתיב שכל ערכו בכותרת חייב לענות **ישירות**. אם ההרכבה מייצרת הפניה,
לרשום את הצורה בלי לוכסן במפורש ולהעביר את הבקשה פנימה — לא להפנות.

מלכודת: העברה שממחזרת רק את ה-endpoint הפנימי מדלגת על מידלוור
האימות של תת-האפליקציה. התוצאה נראית נכונה (`401` תקין) אבל **דוחה
טוקנים תקפים**. יש להעביר לאפליקציה כולה.
