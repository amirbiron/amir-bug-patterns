## H1. תווי BiDi בהערות מפילים לינטרים

**חומרה:** MEDIUM — מפיל CI, וההודעה לא אומרת מה קרה
**חזר 3 פעמים באותו פרויקט**

### איך זה נראה

הערה בעברית שנכתבה במעבד טקסט, הועתקה מדפדפן, או עברה דרך צ'אט —
עלולה לכלול תווי בקרה **בלתי נראים**:

| תו | שם |
|---|---|
| `U+200F` | RIGHT-TO-LEFT MARK (RLM) |
| `U+200E` | LEFT-TO-RIGHT MARK (LRM) |
| `U+202A`–`U+202E` | embedding / override |
| `U+2066`–`U+2069` | isolate |

הם לא נראים בשום עורך. הקוד נראה תקין לגמרי.

### מה קורה

- `bandit` → `B613` (Trojan Source, CVE-2021-42574)
- `ruff` → `PLE2502`
- CodeFactor → "3 issues" בלי לומר אילו

הכלים מחמירים כי תו BiDi יכול לגרום לקוד להיראות אחרת ממה שהמהדר
קורא — טכניקת התקפה אמיתית. בהערות בעברית זה תמים לגמרי, אבל הכלי
אינו יכול להבחין, ובצדק.

### מלכודת ב-debug

CodeFactor דיווח "3 issues" בלי פירוט. הנחתי `F811` (שהיה קיים בריפו
ממילא) והלכתי לכיוון הלא נכון. **רק הרצת `bandit` ישירות גילתה.**

כשלינטר מדווח מספר בלי שמות — להריץ את הכלים אחד-אחד, לא לנחש לפי
מה שכבר ידוע על הריפו.

### התיקון השורשי

בדיקה שסורקת את כל קבצי ה-`.py`:

```python
from pathlib import Path

# ה-escapes מכוונים: התווים עצמם בקובץ הזה היו מפילים את הבדיקה על עצמה
BIDI = ("\u200e", "\u200f", "\u202a", "\u202b", "\u202c",
        "\u202d", "\u202e", "\u2066", "\u2067", "\u2068", "\u2069")

# כל התיקיות שמכילות קוד או תוכן שלנו. ההיקף חייב לכסות את מה שהלינטר
# סורק — אחרת הבדיקה עוברת ו-CI נופל.
ROOTS = (Path("app"), Path("tests"), Path("scripts"))

def test_no_bidi_controls_in_source():
    """תווי BiDi בלתי נראים בהערות עברית מפילים את bandit ב-B613."""
    for root in ROOTS:
        for path in root.rglob("*.py"):
            text = path.read_text(encoding="utf-8")
            for char in BIDI:
                assert char not in text, f"{path}: תו BiDi {char!r}"
```

**ההיקף חייב להתאים לזה של הלינטר.** סריקה של `app/` בלבד עוברת בשעה
ש-`bandit` סורק גם את `tests/` ומפיל את ה-CI — בדיוק סוג הפער
ש-`TESTING-PATTERNS.md` T1 מתעד.

**מלכודת:** הבדיקה נכשלת על עצמה אם התווים כתובים בה כליטרלים.
חייבים escape (`"\u200f"` ולא התו עצמו).

**למה בדיקה ולא רק תיקון:** תיקנתי פעם אחת, ואז כתבתי עוד הערות
בעברית בשני PRים נוספים והכנסתי אותם מחדש. הבדיקה תפסה את שניהם.

## H2. `secrets.compare_digest` נופל על non-ASCII

**חומרה:** MEDIUM — מפיל את האימות עצמו

```python
secrets.compare_digest("סוד", user_input)   # TypeError
```

הפונקציה דורשת מחרוזות ASCII בלבד, או `bytes`. סוד שנכתב בעברית לא
מחזיר `False` — הוא **זורק**.

### התיקון

```python
secrets.compare_digest(expected.encode("utf-8"), given.encode("utf-8"))
```

### כלל לזיהוי

כל `compare_digest` על ערך שיכול להגיע מקונפיג, ENV, או DB — לקודד
את שני הצדדים.

## H3. כותרות HTTP אינן UTF-8

**חומרה:** MEDIUM

טוקן שמכיל תו עברי או אמוג'י **נשבר בצד הלקוח לפני שהגיע לשרת** —
הדיבאג בשרת לא יראה כלום.

**הניסוח המדויק:** ערכי כותרת אינם UTF-8, אבל גם אינם "latin-1" סתם.
RFC 9110 מגדיר `field-value` כ-VCHAR של ASCII, ו-`obs-text` שספריות
מפענחות כ-latin-1 מטעמי תאימות היסטורית. **הדרישה האמיתית נגזרת
מדקדוק השדה**, לא מהקידוד:

| שדה | מה הדקדוק דורש |
|---|---|
| `Authorization: Bearer` | `token68` — ASCII בלבד: `A-Za-z0-9-._~+/` ו-`=` בסוף |
| `Authorization` בסכמות אחרות | תלוי סכמה. `Basic` הוא base64, כלומר ASCII |
| `X-*` משלנו | **אנחנו מגדירים.** אם הוא נושא token — ASCII |
| שדות טקסט חופשי | קידוד לפי RFC 8187 (`field*=UTF-8''...`) |

### כלל לזיהוי

ערך שנוסע בכותרת ונושא token או מזהה — הוולידציה בעליית השירות
חייבת לדרוש ASCII **ולומר למה**. הודעה שרק אומרת "לא תקין" תשלח את
המשתמש לחפש במקום הלא נכון. אל תחיל דרישת ASCII גורפת על כל `X-*`
בלי להגדיר קודם מה השדה נושא.

## H4. נורמליזציה של עברית בחיפוש

**חומרה:** LOW — פיצ'ר שנראה שבור

ניקוד וסופיות משנים את המחרוזת בלי לשנות את המילה. חיפוש שלא מנרמל
לא ימצא מסמך שנכתב עם ניקוד, והמשתמש יסיק שהחיפוש שבור.

**שני דברים נפרדים, ולא לבלבל ביניהם:**

- **ניקוד** (`U+0591`–`U+05C7`) — `strip_nikud` מסיר אותו. להפעיל על
  השאילתה **ועל** התוכן המאונדקס, אחרת הנרמול חד-כיווני.
- **אותיות סופיות** (`ךםןףץ`) — `strip_nikud` **אינו** נוגע בהן. הן
  אות אחרת ב-Unicode, ולכן "ארץ" ו-"ארצות" לא יתאימו בהתאמה מדויקת.
  מי שרוצה גם את זה צריך מיפוי מפורש, ורצוי גם stemming.

לפני שמסתמכים על פונקציה קיימת — לוודא מה בדיוק היא עושה. בדיקה
נכתבת במקום שהפונקציה ממומשת, לא בשכבת החיפוש.

ל-Postgres full-text: לוודא שה-configuration מטפל בעברית, או לנרמל
לפני האינדוקס.
