# עברית בקוד ובנתונים

**מתי להחיל:** כל פרויקט שלי. ההערות בקוד בעברית, המשתמשים כותבים
בעברית, וחלק מהמחרוזות בקוד בעברית.

**למה זה מגיע לקובץ נפרד:** זה משטח שרוב הקוד בעולם לא נוגע בו. הכלים
לא נבנו סביבו, והם מפתיעים — לא בהתנהגות שגויה, אלא בהתנהגות נכונה
שלא ציפיתי לה.

## H1. תווי BiDi בהערות מפילים לינטרים

**חומרה:** MEDIUM — מפיל CI, וההודעה לא אומרת מה קרה
**חזר 3 פעמים באותו פרויקט**

### איך זה נראה

הערה בעברית שנכתבה במעבד טקסט, הועתקה מדפדפן, או עברה דרך צ'אט —
עלולה לכלול תווי בקרה **בלתי נראים**:

| תו | שם |
|---|---|
| `U+200F` | RIGHT-TO-LEFT MARK (RLM) |
| `U+200E` | LEFT-TO-RIGHT MARK (LRM) |
| `U+202A`–`U+202E` | embedding / override |
| `U+2066`–`U+2069` | isolate |

הם לא נראים בשום עורך. הקוד נראה תקין לגמרי.

### מה קורה

- `bandit` → `B613` (Trojan Source, CVE-2021-42574)
- `ruff` → `PLE2502`
- CodeFactor → "3 issues" בלי לומר אילו

הכלים מחמירים כי תו BiDi יכול לגרום לקוד להיראות אחרת ממה שהמהדר
קורא — טכניקת התקפה אמיתית. בהערות בעברית זה תמים לגמרי, אבל הכלי
אינו יכול להבחין, ובצדק.

### מלכודת ב-debug

CodeFactor דיווח "3 issues" בלי פירוט. הנחתי `F811` (שהיה קיים בריפו
ממילא) והלכתי לכיוון הלא נכון. **רק הרצת `bandit` ישירות גילתה.**

כשלינטר מדווח מספר בלי שמות — להריץ את הכלים אחד-אחד, לא לנחש לפי
מה שכבר ידוע על הריפו.

### התיקון השורשי

בדיקה שסורקת את כל קבצי ה-`.py`:

```python
BIDI = ("\u200e", "\u200f", "\u202a", "\u202b", "\u202c",
        "\u202d", "\u202e", "\u2066", "\u2067", "\u2068", "\u2069")

def test_no_bidi_controls_in_source():
    """תווי BiDi בלתי נראים בהערות עברית מפילים את bandit ב-B613."""
    for path in Path("app").rglob("*.py"):
        text = path.read_text(encoding="utf-8")
        for char in BIDI:
            assert char not in text, f"{path}: תו BiDi {char!r}"
```

**מלכודת:** הבדיקה נכשלת על עצמה אם התווים כתובים בה כליטרלים.
חייבים escape (`"\u200f"` ולא התו עצמו).

**למה בדיקה ולא רק תיקון:** תיקנתי פעם אחת, ואז כתבתי עוד הערות
בעברית בשני PRים נוספים והכנסתי אותם מחדש. הבדיקה תפסה את שניהם.

## H2. `secrets.compare_digest` נופל על non-ASCII

**חומרה:** MEDIUM — מפיל את האימות עצמו

```python
secrets.compare_digest("סוד", user_input)   # TypeError
```

הפונקציה דורשת מחרוזות ASCII בלבד, או `bytes`. סוד שנכתב בעברית לא
מחזיר `False` — הוא **זורק**.

### התיקון

```python
secrets.compare_digest(expected.encode("utf-8"), given.encode("utf-8"))
```

### כלל לזיהוי

כל `compare_digest` על ערך שיכול להגיע מקונפיג, ENV, או DB — לקודד
את שני הצדדים.

## H3. כותרות HTTP אינן UTF-8

**חומרה:** MEDIUM

כותרות HTTP הן latin-1. טוקן שמכיל תו עברי או אמוג'י **נשבר בצד
הלקוח לפני שהגיע לשרת** — הדיבאג בשרת לא יראה כלום.

### כלל לזיהוי

ערך שנוסע בכותרת (`Authorization`, כל `X-*`) — הוולידציה בעליית
השירות חייבת לדרוש ASCII, ולומר למה. הודעת שגיאה שרק אומרת "לא תקין"
תשלח את המשתמש לחפש במקום הלא נכון.

## H4. נורמליזציה של עברית בחיפוש

**חומרה:** LOW — פיצ'ר שנראה שבור

ניקוד וסופיות משנים את המחרוזת בלי לשנות את המילה. חיפוש שלא מנרמל
לא ימצא מסמך שנכתב עם ניקוד, והמשתמש יסיק שהחיפוש שבור.

- להפעיל `strip_nikud` על השאילתה ועל התוכן המאונדקס.
- ל-Postgres full-text: לוודא שה-configuration מטפל בעברית, או
  לנרמל לפני האינדוקס.
